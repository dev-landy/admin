# Landy Admin

Landy 서버의 API를 소비하는 어드민 콘솔 (Next.js 16 App Router + Ant Design v6).

## 시작하기

1. `.env.example`을 `.env.local`로 복사하고 값을 채운다 (Kakao OAuth 로그인용 `KAKAO_*` 값 필요).
2. 의존성 설치 후 개발 서버 실행:

```bash
npm install
npm run dev
```

http://localhost:3000 접속 → Kakao 로그인 후 어드민 화면으로 이동한다.

## 구조 & 규칙

- 화면: `src/app/(admin)/*` · 도메인 로직: `src/features/*`
- 상세 구조/컨벤션/커맨드는 [CLAUDE.md](CLAUDE.md) 참고

## 배포

Vercel의 `admin-prod` / `admin-dev` 두 프로젝트가 같은 `main` 브랜치를 배포하며,
프로젝트별 환경 변수(`NEXT_PUBLIC_API_BASE_URL`, `KAKAO_REDIRECT_URI`, `NEXT_PUBLIC_APP_ENV=prod|dev`)로 구분된다.
`NEXT_PUBLIC_APP_ENV`는 탭 제목·파비콘·상단 스트립·헤더 배지 색상을 결정한다 (미설정 시 `local`).

계약서 관리는 `/v1/admin/contract-documents` API를 사용한다. 등록은 검수값을 평탄한 본문으로 보내
응답 시 완료한다. OCR은 필요할 때 별도로 요청하며, 제안값을 관리자가 선택해 적용한다. 보관 초안과 최신 OCR 조회의
`204`는 결과가 없는 상태다. 이 계약과 `/draft` 조회를 지원하는 백엔드를 먼저 배포한 뒤 어드민을 배포한다.
웹 페이지의 `/contract-ocr` 주소는 기존 Slack 링크를 위해 유지하며, 구 관리자 API 호출은 사용하지 않는다.

검수 화면은 입력란 아래에 `계약 등록`과 `반려`를 나란히 제공하고, 반려를 누르면 사유를 선택해 확정한다.
두 버튼은 임차인 정보 블록 안에서 스크롤 영역 하단에 고정된다. 필수값이 빠진 상태의 등록 비활성화와
처리 중 중복 클릭 방지는 유지하며, 임차인 정보 블록을 벗어나면 하단 고정도 해제된다.
반려 모달의 `사용자에게 결과 알림 보내기`는 사유 선택 전에는 비활성이다. `중복 제출`을 선택하면 기본으로 끄고,
`내용을 읽을 수 없음`·`계약서가 아님`·`만료된 계약서`는 기본으로 켠다. 선택 후 스위치를 직접 바꿀 수 있으며,
`사유 기본값`·`직접 변경` 상태와 실제 알림 효과를 표시한다. 끄면 해당 계약서는 인앱 알림과 푸시 없이 반려한다.
반려 요청은 사유와 독립적인 `notifyUser` boolean을 명시하며, 같은 업로드의 다른 계약서 결과 알림은 유지한다.
다른 사유를 선택하면 새 사유의 기본값으로 재설정한다. 모달 취소·재열기는 사유와 직접 변경 상태를 초기화하고,
요청 실패나 화면 재조회는 현재 사유와 알림 선택을 유지한다.
`notifyUser`를 지원하는 백엔드를 먼저 배포한 뒤 이 반려 UI를 배포한다.
검수 중에는 해당 임대인의 건물을 선택하거나 이름·주소를 수정하고 새 건물을 추가할 수 있다.
수정·추가는 `수정 예정`·`추가 예정` 초안으로 표시하며, `계약 등록` 요청에서 임차인과 같은 트랜잭션으로 저장한다.
되돌리기·모달 취소·계약서 반려는 건물을 생성하거나 수정하지 않는다. 등록 실패 시 선택과 초안, 임차인 입력을 유지한다.
이름·주소는 각각 Unicode code point 기준 최대 255자이며, 주소를 비우면 등록 요청에 `null`을 보내 기존 주소를 지운다.
건물 목록 조회에 실패하거나 선택한 건물이 해당 임대인의 목록에 없으면 등록을 잠그고 재조회 또는 새 선택을 요구한다.
건물 선택·수정·추가를 지원하는 atomic registration 백엔드를 먼저 배포한 뒤 이 건물 UI를 배포한다.
구 서버는 새 건물 옵션을 무시할 수 있으므로 UI를 먼저 배포하면 문서의 원래 건물에 잘못 등록될 수 있다.
`OCR 분석 (선택)`은 등록 동작 아래에 두며, `이전 검수 입력 불러오기`는 보관된 검수값이 있을 때만 표시한다.
초안과 OCR 제안값은 확인 후 적용하며 편집 중인 입력을 자동으로 덮어쓰지 않는다.
원본은 클릭 확대 없이 표시하고, 1,200px 이상 화면에서는 원본과 입력란을 각각 스크롤한다.
좁은 화면에서는 원본을 기본으로 접고 헤더를 화면 상단에 고정해, 입력 중에도 바로 펼칠 수 있다.
원본은 고정 헤더 아래에서 별도로 스크롤하며, 플로팅 등록·반려 버튼을 가리지 않는 높이로 열린다.
열고 닫을 때 입력값과 페이지 스크롤 위치를 유지한다.
576px 미만 화면에서는 납부일과 각 금액 입력을 한 줄에 하나씩 배치한다.
검수·임차인 수정의 임대료·관리비·보증금은 만원이 기본이며 입력 오른쪽 단위를 눌러 원으로 전환할 수 있다.
단위 전환은 실제 금액을 유지하고 서버에는 원 단위 정수를 보낸다.
계약 시작일·종료일은 `2026-10-01`과 숫자 8자리 `20261001` 입력을 모두 받으며, Enter 또는 포커스 이동 후
`YYYY-MM-DD`로 표시한다. 존재하지 않는 날짜와 미완성 날짜는 저장값으로 적용하지 않는다.

계약서 목록 하단의 `운영 도구` 안에 있는 `계약서 처리 복구`는 `POST /v1/admin/contract-uploads/storage-retries`를 호출한다.
전체 계약서의 보관·삭제 등 파일 작업과 이전 처리 흐름의 임차인 등록·결과 알림을 이어서 처리하며,
OCR을 새로 요청하지 않는다. 응답의 `attempted`는 실패를 포함한 파일 작업 시도 건수이며 등록·알림 건수는
포함하지 않는다. 0건이어도 backoff 등으로 대기 중인 작업이 남을 수 있다. 응답 유실·오류 때도 일부 작업이
처리됐을 수 있으므로 관련 목록을 갱신하고, 자동으로 재요청하지 않는다.

배치 화면은 실행 이력·Step 상세·지연 경고와 Job·상태·종료 코드·대상 날짜 필터를 제공한다.
예약의 실행 시각·활성 여부는 배치 설정 화면에서 변경하며, 수동 실행·실행 재시도는 제공하지 않는다.
집수리 요청 만료·사진 정리 예약도 같은 화면에서 관리한다. 예약 변경은 DB 저장 후 기본 1분 주기의
동기화에서 반영되며 지연될 수 있다. 비활성화해도 이미 실행 중인 작업은 중단하지 않는다.
예약 변경 요청과 최신 목록 재조회가 끝날 때까지 다른 변경과 모달 닫기를 잠근다.
재조회가 실패하면 이전 예약값으로 다시 변경하지 않고 재조회를 요구한다.

목록 조회 실패는 빈 결과와 구분해 오류와 `다시 조회`를 표시한다. 재조회 실패 시 캐시가 있으면
마지막 조회 결과임을 안내하고 유지한다. 사용자 상세의 임차인·FCM 토큰 목록은 서버 페이지네이션을
사용한다.
일반 건물 수정에서는 빈 주소가 기존 주소 유지이며, `주소 삭제`를 선택하면 `clearAddress: true`로
명시적으로 삭제한다. 이름·주소는 각각 Unicode code point 기준 최대 255자다. 기본 건물 구분은 제공하지 않는다.
주소 삭제를 지원하는 백엔드를 먼저 배포한 뒤 어드민을 배포한다.
