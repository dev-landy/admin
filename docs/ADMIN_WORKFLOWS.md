# 관리자 업무 중심 UI 기준

확인일: 2026-10-05. 공개된 기업 디자인 시스템의 원칙과 현재 Landy 관리자 업무를 대조했다. 아래는 이 제품의 선택 기준이며, 다른 회사의 비공개 관리자 화면을 조사했다는 의미는 아니다.

## 업무의 순서

관리자는 먼저 이메일·전화번호·이름·건물·호실로 대상을 찾고, 동명이인과 비슷한 건물을 구분한다. 이어 계약·납부·알림 이력을 확인하고, 필요할 때 정보를 수정하거나 운영 문제를 처리한다. 화면도 대상 찾기 → 결과 확인 → 관련 업무 → 설정 변경 순서로 구성한다.

목록에서는 이름·연락처·건물처럼 대상을 판단하는 정보가 먼저 보인다. ID는 장애 문의와 정확한 조회에 필요한 보조 정보로 유지한다. 금액의 원/만원 단위, 청구 주기와 납부 조건, 업무 대상일과 실제 실행 시각은 합치거나 생략하지 않는다.

승인된 관리자가 상세에서 이미 조회할 수 있는 이메일·전화번호·이름은 목록에서도 원문으로 표시한다. 같은 이름과 비슷한 연락처를 구분하는 업무를 목록 마스킹으로 방해하지 않는다. 조회 권한 검사는 유지하며, 검색 입력의 로그 제거와 JWT·FCM 기기 토큰 가림은 개인정보 표시 정책과 별개로 유지한다.

Next 개발 서버도 검색·복귀 URL과 OAuth 코드가 들어갈 수 있는 쿼리 요청의 터미널 로그를 생략한다. 이 설정은 개발 모드에 적용되며 운영 빌드 동작은 바꾸지 않는다.

## 반복해서 적용할 경험칙

- 페이지 제목과 대상 정보만 읽어도 어떤 기록을 보고 있는지 알 수 있게 한다.
- 표의 왼쪽은 대상 식별, 가운데는 판단에 필요한 상태·기간·금액, 오른쪽은 행 작업에 쓴다. 서로 다른 업무의 ID를 독립 열로 계속 추가하지 않는다.
- 사용자가 비교해야 하는 정보는 표로 유지한다. 설명이 길거나 드문 상세 정보는 명시적인 상세 보기에서 제공한다.
- 주된 행 작업과 더보기는 한 줄로 유지한다. 메뉴는 hover에만 의존하지 않고 키보드로도 접근하며 행별 대상 이름을 갖는다.
- 삭제와 권한 변경은 대상과 영향을 확인한다. 삭제할 수 없는 이유를 알고 있다면 실행 전에 표시한다. 조회 조건 변경으로 행이 사라지면 그 행의 확인창도 정리한다.
- 검색 조건은 URL과 폼에 복원하며, 관련 화면 이동과 목록 복귀에서도 유지한다. 초안 입력과 적용한 조건은 구분한다.
- 조회 조건은 관리자가 직접 접고 펼칠 수 있게 한다. 접어도 입력 필드를 제거하지 않으며 미제출 초안과 적용한 조건을 모두 유지한다.
- 필터로 0건이 된 상태, 처음부터 기록이 없는 상태, 조회 실패와 로딩은 각각 다른 안내와 복구 동작을 제공한다.
- 별도 페이지를 방문하지 않고도 전체 결과 수와 현재 범위를 읽을 수 있게 한다. 금액은 정렬하고, 긴 연락처·주소·시각은 읽을 수 있게 보존한다.
- 발송·구독·백그라운드 푸시는 작업별로 구분한다. 탭 전환만으로 실행하거나 입력 초안을 지우지 않는다.
- 작은 화면에서도 정보와 작업에 접근할 수 있게 한다. 먼저 열을 단순화하고, 비교 정보가 남아 필요할 때만 표 내부 가로 스크롤을 사용한다.

## 화면 크기와 정보 배치

모바일은 대상별 카드에 식별정보·상태·주요 작업을 먼저 표시하고 추가 정보를 펼쳐 읽는다. 중간 화면은 핵심 열과 상세 펼침을 사용하며, 큰 데스크탑은 비교할 항목을 독립 열로 표시한다. 화면이 넓어도 실제 목록 영역에 전체 열이 들어가지 않으면 압축 표를 선택한다. 대화상자처럼 목록 영역이 760px보다 좁으면 카드로 전환한다.

압축 표의 추가 정보는 행 클릭·재클릭 또는 행에 포커스를 둔 Enter·Space로 펼치고 접는다. 별도 `+` 열·문구·꺾쇠는 표시하지 않는다. 링크·작업 버튼·입력·스위치와 텍스트 드래그 선택은 펼침을 실행하지 않는다. 넓은 표의 원래 행 동작과 모바일 카드의 펼침은 유지한다. 작업 열(`action`/`actions`)은 헤더와 버튼 묶음을 가운데로, 금액 열(`admin-numeric`)은 헤더와 본문을 오른쪽으로 정렬한다. 날짜·주소·상태를 함께 표시하는 설명 셀은 왼쪽 정렬을 유지한다.

행 안의 정보 블록과 작업 버튼은 모두 세로 중앙에 맞춘다. 대상 셀의 줄 수가 늘어나도 상태·시각·금액이 행 위쪽에 붙지 않으며, 펼친 추가 정보는 별도 행에서 읽는다.

각 표의 `columnSizing`은 데이터 종류·서식·문자 길이에서 정한 최소 폭, 읽기 좋은 기준 폭(`preferred`), 추가 공간의 가중치(`grow`)를 지정한다. 작업·ID·금액·단일 상태처럼 고정할 열은 가중치 0으로 유지하고 이메일·주소·수신 대상·오류 설명에는 여유 공간을 나눈다. 표는 부모의 가용 폭을 모두 사용하며, 기준 폭을 채운 뒤 남는 공간도 표 안의 확장 열에 나눠 배분한다. 첫 열 하나에 자동으로 몰아주거나 표 옆에 빈 영역을 만들지 않는다. 긴 상태명·종료 코드는 별도 최소 폭을 확보한다.

1200px부터 기본 메뉴에 글자 라벨을 표시하고, 더 좁은 중간 화면에서는 메뉴 레일을 사용한다. 관리자가 선택한 메뉴 접힘 상태는 저장한다. 모바일 메뉴는 별도 패널에서 연다. 건물과 임차인처럼 가까운 업무도 서로 다른 아이콘을 사용한다.

메뉴 그룹은 `서비스 관리`, `알림 관리`, `시스템 관리`다. 접는 순간 그룹 제목은 숨기고 그룹 사이에 짧은 구분선을 표시한다. 로고·메뉴 폭·아이콘 위치·그룹 간격·하단 조작은 지연 없이 같은 240ms 곡선으로 함께 전환한다. 워드마크와 메뉴 글자는 접힌 영역에 잔상을 남기지 않으며 펼칠 때 확보되는 공간에 맞춰 나타난다. 모션 감소 설정에서는 즉시 전환한다.

하단의 접기·로그아웃도 아이콘과 라벨을 유지한 채 로고와 같은 전환 순서를 사용한다. 접기 방향은 이중 꺾쇠로, 로그아웃은 전원 아이콘으로 표시한다.

필터의 기본 조건과 조회·초기화는 모든 화면에서 항상 표시한다. 검색 조건 헤더와 필터 전체를 접는 기능은 두지 않는다. ID·세부 기간·드문 상태는 상세 조건에 두며, 상세 조건만 접고 펼칠 수 있다. 숨긴 상세 입력에 오류가 있으면 자동으로 펼쳐 수정할 수 있게 하며, 접기·재조회 후에도 입력을 유지한다. 페이지당 항목 수를 바꾸면 첫 페이지부터 조회하며, 결과가 없으면 페이지 이동 바를 표시하지 않는다.

사용자 상세의 계정 정보와 설정은 관련 목록 앞에 두며, 모바일 설정은 접어서 볼 수 있다. 연락처에는 수신 유저·임차인 등 주체를 명시한다. FCM 테스트는 같은 화면에서 유저와 등록 기기를 선택한 뒤 메시지와 대상을 확인한다. 조회용 ID를 다른 화면에서 옮겨 적는 흐름을 기본 동작으로 사용하지 않는다.

계약서 검수는 1200px부터 원본과 입력을 나란히 배치한다. 중간 화면은 원본 40%·입력 60%, 1600px부터는 각각 50%를 사용한다. 원본 확대와 스크롤은 입력 영역을 밀지 않는다. 등록이 비활성일 때는 실제로 필요한 입력을 안내하며, 예시 문구를 입력값으로 취급하지 않는다.

## 공통 UI 단위

본문·폼·팝업·코드 표시는 Pretendard Variable v1.3.9를 함께 사용한다. 루트 레이아웃에서 jsDelivr의 공식 가변 서브셋 CSS를 불러오고 실제 문자에 해당하는 WOFF2만 요청한다. 버전이 고정된 CSS와 폰트는 `max-age=31536000, immutable`으로 브라우저가 캐시한다. 전체 폰트 파일을 로컬 빌드에 포함하지 않으며, 공식 로고의 SVG 윤곽은 별도 브랜드 자산으로 유지한다.

유저 목록의 가입일은 모든 화면 크기에서 기본 정보로 표시한다. 중간 화면은 가입·권한과 함께, 모바일은 기본 필드로 보여주며 넓은 화면에서는 독립 열로 비교한다.

기기 OS도 모든 목록에서 기본 표시한다. 삭제되지 않은 FCM 등록 정보에 Android와 iOS가 모두 있으면 각각 배지로 표시하며, 확인할 정보가 없으면 중립색 미확인 배지를 보여준다. 가입 경로나 현재 사용 기기를 추정하지 않는다. 토큰 비활성화 후 사용자 목록도 갱신한다.

사용자 전체 조회에는 탈퇴 계정도 포함한다. 탈퇴 여부는 `deletedAt`으로 판단해 가입 단계와 별도로 탈퇴 배지·탈퇴일을 표시한다. 가입 상태 필터의 탈퇴는 탈퇴 계정만 조회하며, 다른 가입 단계는 사용 중인 계정에 한정한다. 탈퇴 계정의 운영 작업은 표시하지 않는다. 기존 API 요청의 기본 계정 범위는 사용 중인 계정으로 유지하고, 새 관리자 목록은 전체 범위를 명시한다.

탈퇴 계정의 상세는 보관 정보의 읽기 전용 화면이다. 탈퇴 시점 이전에 만들어져 현재 DB에 남아 있는 소속 건물·임차인을 조회하며, 탈퇴 당시의 정확한 스냅샷이나 삭제된 데이터 복구를 제공하지 않는다. 삭제된 FCM 토큰과 계약 원본은 조회할 수 없다. 권한·알림 설정은 보관된 값으로만 표시하고 수정·삭제·발송·사용자 토큰 발급은 제공하지 않는다. 보관 건물에서 임차인을 볼 때는 같은 사용자의 보관 임차인 목록에 건물 ID 필터를 적용하며, 활성 전용 건물·임차인 API로 이동하지 않는다. 연결 호실이나 건물명이 없으면 정보 없음으로 표시하며 주차 등 다른 의미로 추론하지 않는다.

운영용 사용자 선택기는 ACTIVE 범위의 정확한 ID 조회로 선택을 확인한다. 탈퇴 계정의 상세 조회가 허용돼도 운영용 후보로 선택할 수 없으며, 기존 입력의 사용자 ID가 더 이상 활성 후보가 아니면 선택을 해제한다.

각 조회 결과의 정렬 기준과 오름차순·내림차순을 선택할 수 있다. 서버 페이지 목록은 필터와 정렬을 먼저 적용한 뒤 페이지를 나누며, 전체 배열을 조회하는 목록도 정렬한 전체 배열에서 페이지를 나눈다. 정렬을 바꾸면 해당 목록의 첫 페이지로 돌아가고 검색 조건·다른 하위 목록 상태는 보존한다. 같은 날짜에는 고유 ID를 보조 기준으로 사용한다. 기존 기본 정렬과 계약서 검수 대기열의 오래된 요청 우선 순서는 유지한다.

- `BrandLogo`: 공식 하우스 심볼·영문 Landy 워드마크를 사이드바, 모바일 메뉴와 로그인에서 공유한다. 집 바닥을 Land의 일반 글자 기준선에 맞추고 y 꼬리만 아래로 둔다. 세로 중앙 정렬은 y 꼬리를 제외한 집과 글자 본체의 영역을 기준으로 한다. Admin은 작은 보조 글자로 같은 기준선에 맞춘다. 축소 메뉴에는 심볼만 표시하며 다크 표면에서는 흰색을 사용한다. 사이드바 로고 영역·환경 헤더·모바일 메뉴 헤더는 모두 테두리를 포함한 64px를 사용한다.
- `ThemeSelector`: 모니터·해·달 SVG 버튼의 팝업에서 시스템·라이트·다크를 선택한다. 선택은 기존 브라우저 저장소에 남으며 모바일에서도 햄버거 왼쪽에 표시한다. 선택·Escape로 닫으면 버튼으로 포커스를 돌리고, 바깥 입력란 클릭 시에는 입력란의 포커스를 유지한다.
- `Switch`: 둥근 트랙을 기본 높이 26px·최소 폭 72px로 표시하고 20px 손잡이 주변에 3px 여백을 둔다. 글자와 손잡이 사이의 여백도 함께 조정한다. 활성 색상은 서비스의 푸른 강조색, 비활성 색상은 대비를 확보한 중립색을 사용하며 실제 조작 영역은 최소 44px다.
- `NativeSelect`: 페이지당 항목 수 등 네이티브 선택 동작의 화살표, 내부 여백, 높이와 포커스를 공유한다. 높이는 데스크톱 36px, 모바일 44px다.
- `FilterActions`: 조회·초기화 버튼에 입력 필드와 같은 라벨 공간을 둔다. 오류 문구가 나타나도 다른 입력을 아래로 밀지 않으며, 버튼이 별도 행에 놓이면 빈 라벨을 숨긴다.
- `RefreshButton`: 새로고침 아이콘을 항상 표시하고 조회 중에는 같은 자리를 로딩 아이콘으로 대체한다. 로딩 여부로 버튼 폭과 상단 작업 영역의 줄바꿈을 바꾸지 않는다.
- `FormFieldGrid`: 함께 비교하는 두 입력을 같은 너비로 배치하고 보조 버튼을 입력행에 맞춘다. 필드 영역이 좁으면 세로로 쌓는다.

새 화면에서 같은 목적의 컨트롤을 만들 때 이 단위를 재사용한다. 기간 단축 선택처럼 입력의 보조 행동은 라벨 높이를 바꾸지 않도록 입력 아래에 둔다.

필터는 페이지 폭 대신 실제 필터 영역의 폭에 맞춘다. 기본 필드는 넓을 때 같은 행, 중간 폭에서는 같은 폭의 두 열, 좁을 때는 모두 한 열로 배치한다. 상세 조건의 트리거 위치·높이는 접힘 여부에 따라 바꾸지 않는다. 모바일 입력과 주요 조작은 44px를 사용하며 스위치는 시각적 트랙을 유지한 채 클릭 영역을 넓힌다.

## 검증 경계

시스템·라이트·다크를 헤더와 로그인에서 선택한다. 기본은 시스템이며 명시한 모드는 OS 설정보다 우선한다. 선택은 해당 브라우저 원점에 저장되고 시스템 모드는 OS 변경을 따라간다. 저장소 사용이 막히면 현재 세션의 선택은 유지하며 다음 진입은 시스템 설정으로 시작한다.

팔레트는 `src/config/theme.ts`의 단일 데이터에서 초기 HTML CSS와 Ant Design 토큰으로 공유한다. 중립적인 슬레이트 표면, 본문·보조 텍스트, 밝은 링크와 깊은 버튼 배경을 구분한다. 의미 있는 상태와 포커스는 색상과 텍스트로 함께 표시한다. 초기 스크립트는 색상 선택만 적용하고 서버 렌더와 첫 클라이언트 렌더의 구조는 유지한다.

사용자가 테마를 바꾸면 공통 `ThemeTransition`이 전체 화면과 열린 포털을 0.35초 ease로 함께 전환한다. 지원 브라우저는 한 화면의 교차 전환을 사용하고, 나머지는 같은 시간의 색상 전환을 적용한다. 초기 로딩과 모션 감소 설정에서는 전환 애니메이션을 적용하지 않는다. 전환으로 폼·포커스·스크롤을 초기화하지 않는다.

레이아웃 변경은 스냅샷의 모양만 검사하지 않는다. 실제 검색·목록 복귀·보조 링크·확인 취소·편집 보호·작업 중 상태를 함께 확인한다. 로컬 합성 데이터와 실제 관리자 API로 검증한 결과를 운영 데이터 검증이나 카카오 로그인 검증으로 확대하지 않는다.

검색 API와 관련 조회의 서버 구현은 독립 `landy-admin` 모듈에 둔다. 필터링과 총수 계산은 페이지 분할 전에 같은 조건을 사용해야 한다. 관리자 UI 개선을 일반 서비스 도메인 코드 변경의 근거로 삼지 않는다.

새 검색 조건과 표시정보를 지원하는 관리자 서버를 먼저 배포한 뒤 어드민 UI를 배포한다. 조회용 표시 필드는 이전 서버에 대한 대체 표현을 두지만, 새 조건을 무시하는 서버에서 검색 기능이 동작한다고 안내하지 않는다.
